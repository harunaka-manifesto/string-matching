# GoPay App Copy: Figma migration package

> **Status (2026-09-29): imported.** The `import-packs/` were imported into the Figma file "GoPay Strings" as `# Legacy 1–5` collections, 16,393 variables in total. Do not add new strings to the legacy collections. See `docs/plugin-copy-rules.md`.

Generated by `scripts/copy-migration/migrate.py` from the String Tracker CSVs, following `docs/copy-identity-architecture.md` (section 15 contract). Validated by `scripts/copy-migration/validate.py`. See `reports/validation-report.md` for the numbers.

## What was generated

- `collections/<collection>/EN.json` + `ID.json`: DTCG-style string tokens for **active** copy. Identical token paths in both files, only `$value` differs. Variable name = `<domain>/<platformKey>` (exactly one group level; the group is the collection/domain folder name, e.g. `transport/gopay_krlbooking_adjustedprice_alert`). File shape: `{ "<domain>": { "<platformKey>": { ...token } } }`.
- `collections-draft/<collection>/EN.json` + `ID.json`: same shape for **draft** (exploration) copy. Kept apart so production imports and dev bundles never pick them up. Import only if writers/designers want drafts in Figma.
- `registry/copy-registry.jsonl`: current truth per entity (Copy ID, `name` (`<domain>/<platformKey>`), `semanticPath` (old `<feature>/<screen>/<context>/<leaf>`), collection, platformKey, legacyKeys, legacySources, EN/ID values, metadata). Includes archived and import-held entities that are not in the JSON.
- `registry/migration-ledger.jsonl`: append-only. `legacyFingerprint -> copyId` lines plus entity snapshots. **Do not delete or edit it.** Reruns read it, so Copy IDs and platformKeys never regenerate.
- `reports/`: `migration-manifest.csv` (every non-empty source record, incl. ignored headers), `review-required.csv`, `duplicate-analysis.csv`, `shared-promotion-candidates.csv`, `common-cta-analysis.csv` (per-CTA breakdown), `validation-report.md`. Dotfiles there are machine summaries.

Each token also carries a 3-line-max `$description` (line 1 `cp_<ID>`; line 2 human context `Domain › Feature › Screen › Context › Role`, Title Case, filler segments general/shared/main skipped; optional line 3 `Note: ...` only when the source row has a note) and `$extensions["com.gopay.copy"]` (`id`, `platformKey`, `status`, `semanticPath` = the old 4-segment semantic path, kept so nothing is lost). Whether Figma keeps these on import is unverified.

## How to import (per collection)

1. In the Figma library file, open Local variables and create a collection named exactly like the folder (for example `transfer`). Because names carry a domain group (`<domain>/<platformKey>`), the group keeps domains apart, so all domain files may be imported into the same single collection until it approaches ~4,000 variables (the Figma per-collection cap); split into several collections beyond that.
2. Import `EN.json` into it (native DTCG variable import, where enabled for your plan/org; otherwise a DTCG importer plugin such as "Variables JSON Import").
3. Import `ID.json` as a second mode of the same collection (import into the existing collection, adding a mode; some importers name modes from the file, so rename modes to `EN` and `ID`).
4. Verify: token count equals the count in `reports/validation-report.md`, and the two modes show different values.

Test one small collection first (`shared`, `finance`). Figma's native JSON variable import was announced at Schema 2025 and was still rolling out when this was written; the exact mode-import UI could not be verified from here.

## Important

- **Copy IDs and registry metadata are authoritative outside the raw token JSON until the later plugin writes them into Figma variable pluginData / descriptions.** Token import alone does not satisfy the identity architecture (no `sharedPluginData("copy","id")`, no platformKey, no legacy keys, no provenance).
- Entities with blocking content problems are **held out of the JSON** but stay in the registry with `importHeld: true` (see `metadata.heldReasons`): missing EN/ID on active copy, EN/ID placeholder mismatch, malformed or unnameable positional placeholders (`%s`), packed plural variants, EN/ID swaps, and values that are exactly one `{placeholder}` (a DTCG importer may read it as an alias reference; flip `HOLD_ALIAS_HAZARD` in `migrate.py` to include them).
- Archived (obsolete) copy is registry-only.
- Feature names come from legacy keys or (when no key) the sheet section, with a small token-alias table. There is no curated feature alias registry yet, and most rows have no resolvable role (fallback role `text`, flagged `UNRESOLVED_ROLE`). Context lives in `$description`, not the name; platformKeys (and therefore variable names) are frozen.
- platformKey collision suffixes follow the architecture (`_2`, `_3`), not the `_key` suffix in the task prompt.
- **Shared merge (2026-09-29, writer review):** ambiguous shared candidates were promoted into `shared`. Near-identical wordings (case, trailing `?!.:…`, `&`/`and`, `okay`/`ok`, curly quotes) collapse into one entity using the dominant EN and ID, for example `Top up?` becomes `shared/gopay_shared_topup_cta` = "Top up". The other entities are archived with `metadata.mergedInto`, and their keys are kept in the shared entity's `legacyKeys`. Ledger events: `merge` and `rekey` (reason `shared-merge`). Values containing digits or placeholders stay contextual.
- **Whole-value placeholders removed:** strings whose entire value is one `{placeholder}` are archived with `metadata.removedReason=WHOLE_VALUE_PLACEHOLDER`. They are not imported and have no review item. Their keys stay reserved.
- **Rev 2 rekey (2026-09-29, one-time, pre-release):** all 17,205 migration-generated keys were regenerated to `gopay_<domain>[_feature][_screen][_context]_<role>[_qualifier][_n]` (words concatenated, filler `general`/`shared`/`main` dropped, ≤100 chars, `platformKeySource=generated-rev2`). The 3,397 legacy keys and every Copy ID are unchanged. Each old generated key is kept in `legacyKeys`, and the change is logged as `rekey` events in the ledger. Reruns read those events, so keys stay frozen from now on.
